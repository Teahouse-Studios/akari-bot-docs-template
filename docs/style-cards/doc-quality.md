# 文档质量规范

适用于 `docs/` 下六种语言的全部页面，共 42 页 × 6 语。句子与文风看这一份，页面骨架看 `page-structure.md`。

版本基线：VitePress `2.0.0-alpha.21`、`@m3e/web` `2.10.3`、`@m3e/icons` `1.0.21`、Node.js `>=22.12.0`。版本号以 `package.json` 与 `package-lock.json` 为准。

## 1. 取舍顺序

两处要求相冲突时，按下面的顺序定：

1. 事实准确。属性、默认值、命令、路径以源码与已安装的包为准。
2. 读者可用。一页说清一件事，读者照着能做完。
3. 全站一致。同一个概念只有一个词，六种语言互相对得上。
4. 句子简短。删掉不承担信息的句子。

## 2. 读者与语气

- 读者称“你”。主题称“主题”。组件与接口用代码里的原名，例如 `m3e-button`。
- 不用“我们”“大家”“笔者”。
- 说明功能写“此属性控制……”“这一页介绍……”“`parallel` 把两页并到一个入口”。
- 操作要求写“请……”，条件写“若……”“当……”，能力写“支持”“不支持”。
- 语气平实。不用感叹号、表情符号、比喻、拟人。
- 不写评价性说法，例如“强大”“优雅”“开箱即用”“非常方便”。

## 3. 句子

- 一句话只承载一个动作、一个条件或一个结果。平均 35–50 字。
- 不用分号。并列内容拆成两句，或改成列表。
- 少用连续定语。一串“的”拆成两句，先说对象，再说条件或动作。
- 指代明确。重复写“此属性”“这一页”，比“它”“其”好读。
- 一句里出现两个以上的“并”“且”“而”时，拆开重写。
- 数字、单位、版本号照实写。不改写，不省略。

示例：

改前：开发服务器；修改 Markdown 即时更新，修改 `config.ts` 自动重启

改后：启动开发服务器。修改 Markdown 即时更新，修改 `config.ts` 后自动重启

## 4. 段落

- 一段 1–3 句。先给结论，再补原因或边界。
- 连续正文超过 80 个汉字就分段。按语义拆成两三段，不按句号机械切。
- 列表项同样按一段算。一项只讲一件事，超过 80 字就拆成两项，或补一个小标题。
- 代码块前用“示例：”“以下为……”“例如：”引出，说明这段代码做什么。
- 代码块后用“说明：”接列表，逐条解释参数、行为或限制。
- 段落之间用“若”“当”“因此”“这时”承接。不用“接下来”“需要注意的是”这类空过渡。

## 5. 标题

- 用名词或动宾短语：`安装`、`版本基线`、`创建仓库`、`注册图标`。
- 文章页的 H1 写成 `<主题>：<分页>`，分页名取 front matter 的 `tab`，例如“头图：技术细节”。
- H2 放主题，H3 放子主题，H4 放同一功能的变体。层级不跳。
- 不用问句标题，不用“其他”“杂项”“补充说明”这类空标题。
- 改标题文字前先查站内链接。被链接引用的锚点不能改。

## 6. 代码与表格

- 代码块标语言。命令块保持可直接复制，不带提示符与占位输出。
- 行内代码用于标识符、属性、路径、命令、配置键与 CSS 变量。
- 属性表固定四列，列名依次为“属性”“取值”“默认值”“说明”。插槽表两列，事件表两列。列数与顺序六种语言一致，列名各自翻译。
- 表格只放对照数据。步骤、注意事项、限制用列表。
- 单元格里不用分号连两件事。拆成两句，或拆成两行。

说明：上面“不用分号”只约束叙述文字与表格单元格。代码块里的分号原样保留。

## 7. 用词与术语

- 同一概念全站同名。下表是六种语言的口径，新页按它取词。

| 概念 | zh-CN | en-US | ja-JP | ko-KR | fr-FR | ar-SA |
| --- | --- | --- | --- | --- | --- | --- |
| 主题 | 主题 | theme | テーマ | 테마 | thème | السمة |
| 概览分页 | 概览 | Overview | 概要 | 개요 | Vue d'ensemble | نظرة عامة |
| 接口分页 | 接口 | API | API | API | API | API |
| 技术细节分页 | 技术细节 | Details | 詳細 | 세부 사항 | Détails | التفاصيل |
| 浮动分页 | 浮动 | Dock | ドック | 도킹 | Ancrage | الإرساء |
| 属性表头 | 属性 | Attribute | 属性 | 속성 | Attribut | الخاصية |
| 取值表头 | 取值 | Values | 値 | 값 | Valeurs | القيم |
| 默认值表头 | 默认值 | Default | デフォルト | 기본값 | Défaut | القيمة الافتراضية |
| 说明表头 | 说明 | Description | 説明 | 설명 | Description | الوصف |

- 组件名、属性名、事件名、CSS 变量保持原样。不翻译，不改大小写，不加空格。
- 英文缩写只在需要精确指代时保留。第一次出现时用一句中文说明它指什么。
- 不把英文句子逐词翻成中文。先说清这句话在说谁做什么，再用中文重写。
- 界面文案、示例输出与源码同口径。改了文档用词，语言包与示例一起改。

## 8. 标点与引号

- 中文正文用“”和‘’。不用「」，不用英文双引号。
- 中文正文里的分页名、字段名、命令一律用行内代码，不靠引号强调。
- 中文与英文、数字之间加一个半角空格，例如“修改 `config.ts` 后重启”。
- 其他语言按各自的排版规则。法文在冒号、问号、感叹号前加不换行空格，阿拉伯文从右往左排，标点保持原形。
- 代码、命令、URL、文件路径原样保留。不改标点，不换全角。

## 9. 版本号与事实

- 版本号只出现在安装页的基线表与组件接口页的首句。两处必须相同。
- 改版本号前先核对 `package.json` 与 `package-lock.json`。两边不一致时先停下，报告给维护者。
- 属性、默认值、取值来自组件元数据。升级依赖后要按新版本重新核对组件接口页，不能只改版本号。
- 查不到依据的行为、参数、默认值不写。确需保留时标“待确认”。

## 10. 六种语言

- 六种语言同构。同一篇文章在六语中的 H2 数量、顺序与小节含义一致。
- 新增页面或章节时，六种语言一起改。只改一种语言视为未完成。
- 事实、数字、代码、链接完全相同，只改叙述文字。
- H1 的分隔符按语言：中文与日文用全角冒号，法文在冒号前加不换行空格，英文、韩文、阿拉伯文用半角冒号。
- 不逐词直译。按目标语言的语序重写，保留同样的限定条件与失败情形。
- 术语按第 7 节。没有对照的新词，先在六语中统一，再写进对照表。

## 11. 逐句复读

改完不能只看词语。逐句读一遍，逐条对照：

- 主语是否明确，动作与对象是否齐全。
- 前后句是否承接，代词指向是否清楚。
- 能否换成更常见的动词，或更短的说法。
- 是否还有三层以上从句，或一句话里塞了多个条件。
- 数字、版本号、路径、组件名是否与改动前一致。

读起来不顺就重写整句。只改标点不算修好。

## 12. 禁止

- 问句标题，或介绍“本文按什么顺序展开”的句子。
- 口号式、推销式、空洞总结式的表达。
- 长分号链、三层以上从句、没有具体内容的背景铺垫。
- 连续正文超过 80 个汉字不分段。
- 比喻、拟人、感叹号、表情符号。
- 为“更完整”新增未核实的行为、参数或默认值。
- 用批量脚本替换词语，或对叙述文字做查找替换。改写要逐句读过。
- 改代码块、表格数据、front matter、组件属性、站内链接、图注与示例对话。

## 13. 验收流程

1. 逐句复读，对照 `page-structure.md` 检查骨架。
2. 扫标点：`grep -n '；\|「\|」' <改动文件>`，确认命中只在代码块内。
3. 扫版本：`grep -rn '2\.10\.' docs/*/components docs/*/getting-started`，与 `package.json` 对齐。
4. 查同构：同一篇文章在六语中的 H2 标题数一致。
5. `git diff --check`。
6. 改动超过三页时跑 `npm run build`。改到 Markdown 渲染或链接时，另跑 `npm test`。
