# 页面结构

七类页面，各有固定骨架。新增或改写一页时，先定类型，再套骨架。`getting-started/` 下的指导页沿用分类文章页的骨架，写法另有一套，见第 9 节。

## 1. 类型总览

| 类型 | 路径 | 作用 |
| --- | --- | --- |
| 语言首页 | `<语>/index.md` | 站点的入口，讲清这套文档能做什么 |
| 分类文章页 | `<语>/<分类>/<文章>/index.md` | 一个主题概览，下挂接口页与技术细节页 |
| 组件概览页 | `<语>/components/<组件>/index.md` | 组件能做什么，怎么摆 |
| 组件接口页 | `<语>/components/<组件>/api.md` | 属性、插槽、事件、方法 |
| 主题接口页 | `<语>/theme/<主题>/api.md` | 配置字段、导出符号、类型 |
| 技术细节页 | `<语>/theme/<主题>/details.md` | 机制、顺序、边界、失败情形 |
| 示范页 | `<语>/theme/search/dock.md` | 可交互示例与试法 |

## 2. 文首字段

| 字段 | 用在哪 | 写法 |
| --- | --- | --- |
| `title` | 全部页面 | 导航与页面标题。缺省取第一个 `#` 标题 |
| `icon` | 分类文章页 | Material Symbols 图标名，例如 `radio_button_checked` |
| `order` | 分类文章页 | 在分类中的先后，数字小的在前 |
| `badge` | 分类文章页 | 导航上的短标记，可选 |
| `category` | 语言首页 | 归入哪个分类，例如 `getting-started` |
| `tab` | 同组内的每页 | 标签栏上的名字。概览页写“概览”，接口页写“接口” |
| `parallel` | 组内的概览页 | 同组的其他文件，不带 `.md`，例如 `[api, details]` |
| `hero` | 重点页 | 头图。`image`、`alt`、`tagline`、`fit`、`color`、`pattern` |
| `toc` | 全部页面 | `false` 关掉右侧目录 |

说明：`tab` 与 `parallel` 一起决定标签栏。组内每页都写 `tab`，只有概览页写 `parallel`。

## 3. 语言首页

```text
---
title: 概览
toc: false
category: getting-started
icon: home
---

# 概览

一句话说明这套文档是什么。

## 特性
卡片或列表。每项一句，讲读者能拿到什么。

## 快速开始
最小代码块，两三条命令。

## 接下来阅读
三条以内站内链接，各带一句说明。
```

说明：首页不讲内部实现。需要讲的放分类文章页。

## 4. 分类文章页

```text
---
icon: <图标名>
order: <序号>
tab: 概览
parallel:
  - api
  - details
hero: <可选头图>
---

# <主题>

一句说明这个主题覆盖什么。链接到同组的接口页与技术细节页。

## <读者要做的第一件事>
示例代码或 demo 组件，随后用列表说明参数。

## <下一个主题>
同上，一个 H2 只讲一件事。

## 使用建议
可选。只在有取舍时写，说清什么情况下选哪个。
```

说明：H2 按读者要做的事拆，不按源码文件拆。小节顺序与接口页的字段顺序一致，读者不用来回跳。组件概览页与主题概览页都用这套骨架，`parallel` 分别写 `[api]` 与 `[api, details]`。

## 5. 组件接口页

```text
---
tab: 接口
---

# <主题>：接口

以下内容来自 `@m3e/web` <版本> 的组件元数据。

## <组件标签名>

| 属性 | 取值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `variant` | `filled`、`text` | `text` | 外观 |

| 插槽 | 内容 |
| --- | --- |

| 事件 | 时机 |
| --- | --- |
```

说明：

- 首句只写版本，不写别的。版本与安装页的基线表一致。
- 一个组件一个 H2。同一组件的插槽、事件表紧跟属性表，不另起小节。
- 取值列写全，默认值列写代码原值。没有默认值时写“无”。
- 表格不写用法与建议。用法回概览页。

## 6. 主题接口页

````text
---
tab: 接口
---

# <主题>：接口

## <导出符号或配置字段>

```ts
签名
```

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |

## <下一个符号>
````

说明：

- 一个符号一个 H2，顺序与概览页出现的顺序一致。
- 签名用 `ts` 代码块，只保留读者会用到的类型。
- 字段表四列：字段、类型、默认值、说明。与组件接口页的表头同名。

## 7. 技术细节页

```text
---
tab: 技术细节
---

# <主题>：技术细节

## <机制一>

一句结论。列表逐条说明触发条件、顺序与结果。

## <机制二>

同上。边界、超时、回退另起一项。
```

说明：

- 只写读者会遇到的行为与限制。不贴完整源码。
- 每个 H2 开头一句结论，后面用列表展开。列表项超过 80 字就拆。
- 失败情形写清：什么条件下发生，读者看到什么，怎么恢复。

## 8. 示范页

```text
---
tab: 浮动
---

<script setup>
import Demo from "../../../.vitepress/theme/components/content/<Demo>.vue";
</script>

# <示例名>

一句说明这是哪个接口的在线示例。

<Demo />

可以这样试：

- 第一步做什么，看到什么。
- 第二步做什么，看到什么。
```

说明：示范页只放能点的示例与试法，不抄接口页的字段表。

## 9. 指导页

`getting-started/` 下的文章同样用“概览 + 接口 + 技术细节”三页。区别在写法：

- 概览页按操作顺序推进，一步一个小节。
- 接口页列配置函数、字段与默认值。
- 技术细节页讲目录约定、生成规则与常见失败。

## 10. 新页检查

1. 六种语言同路径建页，front matter 与章节数一致。
2. 组内的每页都写 `tab`，概览页写 `parallel`。
3. H1 用 `<主题>：<分页>`。H2 用名词或动宾短语。
4. 代码块标语言，表格表头与同类页面同名。
5. 站内链接带语言前缀，例如 `/zh-CN/theme/layout/api#源码结构`。
6. 跑 `npm run build`，再走 `doc-quality.md` 第 13 节的验收流程。
