# 히어로: 세부 사항

## 색상 추출

히어로가 있는 페이지는 이미지에서 색상을 하나 뽑아 테마의 시드 색상으로 씁니다.

- Material 공식 [material-color-utilities](https://github.com/material-foundation/material-color-utilities)를 사용합니다. 이미지를 128px 이하로 축소하고 주요 색상으로 양자화한 뒤, 각 색상이 인터페이스 테마에 얼마나 어울리는지 점수를 매깁니다. Android가 배경화면에서 색상을 가져올 때 쓰는 것과 같은 알고리즘입니다. 투명한 픽셀과 너무 칙칙한 색상은 제외합니다.
- 추출은 빌드 시점에 `.vitepress/media-colors.ts` Vite 플러그인에서 수행합니다. 빌드된 HTML에 색상이 들어가므로 페이지를 열 때 이미지를 기다리거나 픽셀을 읽지 않으며, 서버 렌더링과 하이드레이션이 같은 값을 씁니다.
- 결과는 이미지 파일의 수정 시각과 크기를 키로 `.vitepress/cache/media-colors.json`에 캐시되며, 바뀐 이미지만 다시 추출합니다. 이미지를 바꾼 뒤 다시 빌드하면 되고, 캐시를 지울 필요는 없습니다.
- 라이트와 다크 이미지는 각각 추출합니다. 낮에는 `light` 이미지의 색을, 밤에 `dark` 이미지를 표시할 때는 `dark` 이미지의 색을 씁니다.
- 원격 이미지는 빌드할 때 한 번 내려받아 추출하고, 성공한 결과는 7일 동안 캐시합니다. 빌드 환경에서 가져오지 못하면 독자의 색을 유지합니다. `color`로 직접 지정할 수도 있습니다.
- 이미지에 충분히 선명한 색이 없을 때도 독자의 색을 유지합니다.

## 로딩

- 본문 이미지는 Markdown을 렌더링할 때 `loading="lazy"`와 `decoding="async"`가 붙습니다. HTML에 직접 쓴 `<img>`도 마찬가지입니다. 명시한 `loading`이나 `decoding`은 덮어쓰지 않습니다.
- 브라우저에서 본문 이미지는 `.akari-lazy-media`로 감싸집니다. 이미지가 도착하기 전에는 막이 이미지를 덮고 가운데에 `m3e-loading-indicator` 로딩 볼이 표시됩니다. 막의 크기는 빌드 시 기록한 이미지 크기, 색은 추출한 색을 사용하며, 로드가 끝나면 MD3의 `emphasized-accelerate`로 페이드 아웃합니다. `<picture>`는 `<source>`와 함께 감싸므로 소스 선택 방식은 그대로입니다.
- 히어로도 같은 로딩 볼을 이미지 카드 위에 덮고, 현재 라이트/다크 모드에서 보이는 이미지만 기다립니다. 다크 이미지는 라이트 모드에서 내려받지 않으며 그 반대도 같습니다.
- 로딩이 빠를 때 막이 깜빡이지 않도록 약 120ms 늦게 페이드인합니다. 페이드 아웃에는 MD3 시간·이징 토큰을 사용합니다. 동작 줄이기가 설정되어 있으면 애니메이션 없이 막이 바로 나타나거나 사라집니다.
- `ImagePreview` 구성 요소의 썸네일은 자체 테두리를 쓰며, 로드가 끝날 때까지 빌드 시점 비율로 자리를 잡고 같은 색의 로딩 볼을 보여 주며 클릭을 받지 않습니다. 미리보기를 열어도 전체 이미지가 도착할 때까지 같은 비율과 색으로 볼을 표시합니다. 모서리와 클릭 영역을 바꾸지 않기 위해 본문 막으로 감싸지 않습니다.

## 제목

히어로를 설정하면 페이지 제목이 히어로 카드에 표시되고 Markdown의 첫 번째 `# Title`은 숨겨지므로, 페이지에 보이는 `h1`은 여전히 하나뿐입니다. 제목 텍스트는 프런트매터 `title`에서 가져오고, 없으면 첫 번째 `#` 제목에서 가져옵니다. 이는 VitePress의 페이지 제목 규칙과 같습니다. 히어로 안의 제목에는 `data-akari-page-title`이 있으며, 이 제목이 앱 바 아래로 스크롤되면 앱 바에 페이지 제목이 표시됩니다.

날짜는 페이지 언어에 맞게 형식화됩니다. `2026-05-19`는 중국어 페이지에서 “2026年5月19日”, 한국어 페이지에서 “2026년 5월 19일”로 표시됩니다.

## 레이아웃

- 두 카드는 문서 표면 상단을 채우며, 콘텐츠의 `--akari-doc-max-width`에 제한되지 않습니다. 카드에서 표면의 위쪽·왼쪽·오른쪽 가장자리까지의 거리와 두 카드 사이의 거리는 모두 `--akari-doc-hero-inset`입니다. 카드 모서리는 표면 모서리와 동심원을 이룹니다.
- 제목 크기와 카드 안쪽 여백은 창 너비가 아니라 히어로 자체의 너비에 따라 조정됩니다(컨테이너 쿼리). 내비게이션 드로어가 열려 사용할 수 있는 공간이 좁아지면 제목도 함께 작아집니다.
- 창 너비가 840px보다 좁으면 두 카드가 위아래로 쌓입니다. 텍스트가 위에 오고, 이미지는 16:10 비율로 표시됩니다.
- 페이지가 병렬 페이지 그룹에 속하면 탭 바가 히어로 위에 놓이고, 히어로는 탭 바 아래에 같은 거리를 두고 놓입니다. 이렇게 하면 그룹의 모든 페이지에서 탭 바가 같은 자리에 있으므로, 히어로가 있는 페이지와 없는 페이지 사이를 전환해도 탭 바가 튀지 않습니다.
- 이미지에는 `loading="lazy"`와 `fetchpriority="high"`가 붙습니다. 첫 화면에 있는 동안 브라우저는 이미지를 바로 불러오고 그 화면에서 가장 큰 요소로 우선 처리합니다. 창이 좁아 히어로가 첫 화면 아래로 내려가면 뷰포트에 가까워질 때까지 기다립니다. 히어로는 문서 표면 안에 있으므로 페이지를 전환할 때 표면과 함께 사라지고 나타납니다.

## 패턴과 빛

- 두 카드는 같은 패턴을 씁니다. 패턴은 텍스트 카드의 위쪽 끝 모서리와 이미지 카드의 아래쪽 시작 모서리에서 가장 선명하고 각 모서리에서 멀어질수록 옅어지므로, 두 카드가 함께 대각선을 이룹니다.
- 이미지 카드의 패턴은 이미지 아래에 깔려 있어 이미지가 투명한 곳에서만 보입니다. 카드를 가득 채우는 사진은 패턴을 완전히 가립니다.
- 포인터가 카드 위에 머물면 그 주변에 테마 색상의 아주 옅은 빛이 켜집니다. 빛 안에서는 패턴이 조금 더 선명하고, 빛의 가장자리는 단계적으로 옅어지며, 포인터가 떠나면 빛이 서서히 사라집니다. 문서 표면의 `pointermove` 핸들러가 매 프레임 빛의 위치(`--akari-light-x`, `--akari-light-y`)를 기록하며, 마우스와 펜에만 반응합니다. 빛이 켜질지 여부도 포인터로 정합니다. 읽는 사람이 마우스나 펜을 쓰는 동안 `html`에는 `data-akari-hover`가 붙고, 처음 터치하면 제거되며, `(hover: hover)` 미디어 쿼리에는 의존하지 않습니다.
- 패턴은 브라우저에서 고릅니다. 서버 사이드 렌더링에는 패턴이 없고 마운트 후에 패턴이 페이드 인하므로, 서버와 브라우저의 페이지가 일치해 하이드레이션 불일치가 생기지 않습니다.
- 터치 기기에서는 정적인 패턴만 표시되고, 강제 색상 모드에서는 장식이 표시되지 않습니다. 장식은 텍스트와 이미지 아래에 있으므로 선택이나 클릭을 방해하지 않습니다.

콘텐츠 안에서 배경이 있는 요소도 같은 패턴 세트를 씁니다. [타이포그래피](/ko-KR/styles/typography/api#patterns)를 참고하세요.
