# 검색: 세부 사항

## 컨테이너 변환 {#container-transform}

검색 패널은 네이티브 모달 `<dialog>`입니다. Web Animations API로 구현한 M3 컨테이너 변환으로 펼쳐집니다. 언어 선택기와 설정 대화상자도 같은 구현(`useContainerTransform`)을 씁니다.

- 애니메이션되는 것은 언제나 실제 패널이며, 첫 프레임부터 최종 크기로 배치되어 있습니다. 시작 시점에는 버튼 모양의 창(`clip-path` 캡슐)이 패널 자체 검색 바의 시작 부분만 보여 주고, 평행 이동으로 그 창을 버튼 위에 놓습니다. 따라서 첫 프레임은 여전히 “아이콘 + 자리표시자” 검색 상자처럼 보입니다.
- 펼쳐지면서 평행 이동은 0으로 돌아가고, 창은 패널 전체(그림자 포함)로 커집니다. 콘텐츠는 단계적으로 드러나고, 결과 영역과 닫기 버튼이 함께 페이드 인하며, 중간에 빈 표면이 나타나지 않습니다. 애니메이션의 최종 상태가 패널의 평소 스타일이므로, 애니메이션을 제거해도 튀는 현상이 없습니다.
- 버튼의 픽셀 복사본이 창 위에 놓여 함께 움직입니다. 버튼과 패널의 콘텐츠는 크로스페이드하지 않고, 한쪽이 페이드 아웃한 뒤 다른 쪽이 페이드 인합니다(M3 fade through). 열 때는 먼저 패널 표면이 복사본 아래에서 페이드 인하고, 이어서 복사본이 페이드 아웃한 다음, 패널 자체의 검색 바가 페이드 인합니다. 크기가 다른 두 텍스트가 동시에 보이는 일은 없습니다.
- 닫을 때는 왔던 길로 돌아갑니다. 결과 영역과 검색 바가 먼저 페이드 아웃하고, 중간에 버튼 복사본이 페이드 인하여 이어받은 다음, 그 아래에서 패널 표면이 페이드 아웃합니다. 버튼으로 돌아가는 마지막 구간에서는 표현형 모션의 바운스를 포함해 보이는 것이 버튼 자체이며, 실제 버튼과 정확히 같은 모습으로 끝납니다. 따라서 배경이 없는 버튼(톱니바퀴 버튼 등)도 마지막에 배경 조각이 번쩍이지 않습니다. 열거나 닫는 도중에 중단되면 현재 프레임에서 모션이 거꾸로 진행됩니다.
- 창의 크기와 모서리 반경은 버튼의 현재 위치와 크기에서 가져옵니다. 패널의 위치는 애니메이션이 시작될 때 다시 측정되며, 고정 좌표에 의존하는 부분은 없습니다.

| 모션 | 펼치기 | 접기 |
| --- | --- | --- |
| 표준 | 약 300ms, `cubic-bezier(0.2, 0, 0, 1)` | 약 250ms, 바운스 없음 |
| 표현형 | 약 500ms, `cubic-bezier(0.38, 1.21, 0.22, 1)`, 살짝 넘쳤다가 자리 잡음 | 약 400ms, 같은 곡선, 접힐 때 살짝 바운스 |

시스템의 “동작 줄이기” 설정이 켜져 있으면 패널은 애니메이션 없이 열리고 닫힙니다. 네이티브 대화상자가 최상위 레이어 표시, 비활성 배경, `Esc`로 닫기를 제공합니다. 열면 포커스가 입력란으로 이동하고, 닫으면 열기 전에 있던 곳으로 돌아가며, 그 요소를 더 이상 쓸 수 없으면 검색 버튼으로 돌아갑니다.

## 색인 빌드

- VitePress의 로컬 검색이 색인을 만듭니다. 사이트의 Markdown 렌더러로 각 페이지를 렌더링하고, 앵커가 있는 제목에서 섹션으로 나누며, 언어마다 색인을 하나씩 만들어 빌드할 때 각각 파일 하나로 묶습니다. 개발 서버가 실행되는 동안에는 페이지가 바뀔 때마다 색인이 갱신되어 브라우저로 전달됩니다.
- 경로와 앵커는 렌더링된 페이지에서 가져오므로, 재작성된 경로와 사용자 지정 앵커가 있는 제목을 포함해 페이지의 실제 경로 및 제목 id와 일치합니다.
- 본문 텍스트는 태그를 제거한 렌더링된 HTML이며 코드 블록도 포함하므로, 코드 안의 이름도 검색할 수 있습니다. 프런트매터에 `search: false`가 있는 페이지는 제외됩니다.
- 중국어와 일본어는 공백이 없으므로 `Intl.Segmenter`로 단어를 나눕니다. 테마도 검색어를 같은 방식(`tokenizeSearchText`)으로 나누므로, 검색어와 색인이 같은 단어에서 만납니다.

## 매칭과 순위

검색어는 색인과 같은 방식으로 단어로 나뉘고, MiniSearch가 일치 여부를 판단합니다.

- 단어는 입력한 그대로 일치하거나, 더 긴 단어의 앞부분으로 일치합니다. 긴 단어는 길이의 최대 20%까지 편집 거리만큼 철자가 틀려도 됩니다.
- 모든 단어가 일치해야 합니다. 모든 단어를 가진 섹션이 없으면 단어 중 하나라도 가진 섹션을 대신 받아들입니다.
- 관련도는 BM25이며, 가중치는 섹션 제목 4, 본문 텍스트 2, 위쪽 제목 1입니다.

이어서 결과는 입력한 그대로의 검색어를 기준으로 등급별로 정렬됩니다. 여기서 “제목”은 섹션 자신의 제목입니다.

| 등급 | 조건 |
| --- | --- |
| 4 | 제목이 검색어 전체와 정확히 같음 |
| 3 | 제목이 검색어 전체로 시작함 |
| 2 | 제목에 검색어 전체가 포함됨 |
| 1 | 위쪽 제목이나 본문 텍스트에 검색어 전체가 글자 그대로 포함됨(예: 중국어 구절) |
| 0 | 그 밖의 모든 경우 |

높은 등급이 먼저 나옵니다. 등급 4와 3에서는 페이지가 그 섹션보다 앞에 옵니다. 같은 등급 안에서는 MiniSearch의 관련도 순, 그다음 제목순입니다. URL마다 결과는 하나만 남고, 최대 `maxResults`개를 반환합니다. 각 결과에는 일치한 단어(`terms`)가 들어 있으며, 일부만 입력했거나 철자가 틀린 단어도 포함되고, 패널이 이를 강조합니다.

언어마다 색인이 따로 있으므로 결과는 항상 현재 언어에서만 나옵니다.

## 로딩과 캐시

- 각 언어의 색인은 그 언어에서 처음 검색할 때 로드되고, 이후 페이지 안에 캐시됩니다. 개발 중에는 색인이 갱신되면 캐시가 지워집니다.
- 입력은 `debounce`만큼 디바운스됩니다. 새 검색어를 입력하거나 패널을 닫으면 진행 중인 요청이 `AbortSignal`로 중단됩니다.
- 색인을 불러오지 못했거나 형식이 잘못되었으면 패널에 오류와 다시 시도 버튼이 표시됩니다.

## 패널 상태

| 상태 | 표시 내용 |
| --- | --- |
| 빈 입력 | 검색 힌트와 단축키 도움말 |
| 로딩 중 | M3 로딩 인디케이터 |
| 결과 | 페이지 제목, 섹션 제목, 발췌문, 강조된 일치 부분. 현재 항목에는 `secondary-container` 배경이 있습니다. 목록은 하나의 블록처럼 보입니다. 첫 번째 항목의 위쪽 모서리와 마지막 항목의 아래쪽 모서리만 둥글고, 그 사이의 항목은 각진 모서리입니다 |
| 결과 없음 | 다른 키워드를 시도해 보라는 제안 |
| 실패 | 오류 원인과 다시 시도 버튼 |

결과를 열면 VitePress 라우터를 거치므로 SPA 내비게이션이 유지됩니다. 입력란, 결과 목록, 오류 메시지에는 각각 ARIA 이름이 있습니다. 앱 바의 단축키 힌트는 `label-small` 글자 스타일과 완전히 둥근 키캡을 쓰고, 패널의 화살표 키, `Enter`, `Esc` 힌트는 `shape-extra-small` 모서리를 씁니다.

## 알려진 제한 사항

- 로컬 검색은 단어를 매칭하며, 의미 검색이나 동의어는 없습니다. 필요하면 HTTP 백엔드나 등록된 백엔드를 쓰세요. 중국어와 일본어를 단어로 나누는 일은 브라우저의 `Intl.Segmenter`에 의존하며, 이것이 없는 브라우저에서는 공백과 문장 부호에서만 나눌 수 있습니다.
- 로컬 색인은 개발 서버가 실행 중이거나 빌드하는 동안에만 만들어집니다. 개발 서버가 실행되지 않을 때 수정한 Markdown은 다음 `npm run dev` 또는 `npm run build` 후에 검색할 수 있습니다.
