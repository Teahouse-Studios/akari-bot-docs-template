# 검색

검색은 앱 바 오른쪽에 있습니다. 넓은 화면에서는 자리표시자 텍스트와 단축키 힌트가 있는 검색 상자이고, 좁은 화면에서는 원형 버튼으로 줄어듭니다. 클릭하거나 `⌘K`(Windows와 Linux에서는 `Ctrl K`)를 누르면 검색 상자가 검색 패널로 펼쳐집니다.

## 사용법

| 키 | 동작 |
| --- | --- |
| `⌘K` / `Ctrl K` | 어느 페이지에서나 검색 열기 |
| `↑` / `↓` | 결과 사이 이동 |
| `Enter` | 현재 결과 열기 |
| `Esc` | 검색 닫기 |

결과는 페이지와 섹션별로 나열되며, 각각 일치 부분의 발췌문이 함께 표시됩니다. 섹션 결과를 열면 해당 제목으로 스크롤됩니다. 다국어 사이트에서는 현재 언어의 페이지만 반환됩니다.

## 플로팅 검색

검색 필드가 착지할 위치에 `<SearchDock>`을 둡니다. 태그는 상자만 예약하고, 실제 필드는 앱 바를 떠나 그 상자를 측정해 페이지가 열려 있는 동안 그 자리에 머뭅니다.

```md
# 가이드

<SearchDock variant="hero" align="center" placeholder="가이드 검색" />
```

| 속성 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `placeholder` | `string` | `search.placeholder` | 여기에 도킹했을 때의 자리 표시자 |
| `variant` | `"bar" \| "pill" \| "icon" \| "hero"` | `"bar"` | 필드의 모양 |
| `align` | `"start" \| "center" \| "end"` | `"start"` | 아이콘, 라벨, 단축키의 위치 |
| `width` | `string \| number` | 모양의 너비 | 예약 상자의 CSS 길이 또는 픽셀 너비 |
| `height` | `string \| number` | 모양의 높이 | 예약 상자의 CSS 길이 또는 픽셀 높이 |
| `fill` | `boolean` | `false` | 모양의 자연 크기 대신 부모 상자를 채움 |
| `priority` | `number` | `0` | 같은 페이지의 다른 태그보다 우선 |

태그는 전역으로 등록되므로 페이지에서 import할 필요가 없습니다. 필드가 있어야 할 흐름에 두면 주변 레이아웃이 정확한 위치를 정합니다.

이 페이지를 바로 열면 필드가 전환 없이 상자 안에 들어갑니다. 다른 페이지에서 이동하면 앱 바나 이전 도킹 위치에서 날아 들어옵니다. 태그가 없는 페이지로 이동하면 앱 바 쪽으로 돌아가며 사라집니다. 속성을 바꾸면 제자리에서 모양과 정렬이 바뀝니다. 한 페이지에 태그가 여러 개면 `priority`가 가장 높은 것이 쓰이고, 같으면 먼저 렌더링된 것이 쓰입니다.

필드가 도킹되어 있는 동안 앱 바의 제목과 도킹된 탭이 비어 있는 자리를 차지하며, 필드가 돌아올 때 그 자리가 부드럽게 열립니다. 태그는 페이지 영역과 뷰포트 안에 있고 앱 바와 탭 줄에 겹치지 않을 때만 필드를 받습니다. 조건을 만족하지 않으면 필드는 앱 바에 남아 있다가 스크롤로 태그가 보이는 위치에 오면 날아 들어옵니다. 비행 중에 스크롤하면 필드가 태그를 따라가며 마지막 프레임에서 튀지 않습니다. 돌아오는 도중 태그가 다시 사용 가능해지면 현재 위치에서 즉시 방향을 바꾸고 처음부터 다시 재생하지 않습니다. 돌아올 때는 착지한 뒤가 아니라 비행 중에 앱 바의 표면, 글자, 여백으로 변합니다. 비행과 페이드는 테마의 MD3 모션 토큰을 쓰므로 `표준 / 표현형` 설정을 따르고 `prefers-reduced-motion`도 존중합니다.

모든 속성은 [라이브 데모](/ko-KR/theme/search/dock)와 [API](/ko-KR/theme/search/api#searchdock)를 참고하세요.

## 로컬 색인

기본적으로 백엔드가 필요 없습니다. 테마는 VitePress의 로컬 검색이 만드는 색인을 씁니다. 언어마다 하나씩 있으며, 해당 언어에서 처음 검색할 때만 내려받습니다. 페이지는 제목을 기준으로 섹션으로 나뉘고, 일치 여부는 [MiniSearch](https://lucaong.github.io/minisearch/)가 판단합니다. 중국어와 일본어는 단어로 나뉘고, 단어는 앞부분만 입력해도 되며, 긴 단어는 한두 글자 틀려도 일치할 수 있습니다. 개발 서버가 실행되는 동안에는 색인이 수정 내용을 따라갑니다.

## 다른 검색 사용

의미 검색이나 사이트 외부의 콘텐츠가 필요하면 HTTP 엔드포인트나 직접 작성한 JS 함수로 전환합니다.

```ts
// docs/config.ts
search: {
  backend: { type: "http", endpoint: "/api/docs/search" },
},
```

백엔드 작성 방법과 결과 형식은 [API](/ko-KR/theme/search/api)를, 패널의 모션과 색인 빌드·순위 결정 방식은 [세부 사항](/ko-KR/theme/search/details)을 참고하세요.
