# 사이드 내비게이션: 세부 사항

## 레일과 내비게이션 드로어

- **레일**: 페이지 왼쪽의 전체 높이를 차지하는 띠이며, 앱 바는 그 오른쪽에서 시작합니다. `m3e-nav-rail` 안에서 각 카테고리는 `m3e-nav-item`입니다. 하위 항목이 있는 카테고리는 첫 페이지를 가리키고, 하위 항목이 없는 최상위 항목은 그 자체가 링크입니다. 오른쪽의 구분선은 옆에 내비게이션 드로어가 표시될 때만 나타납니다.
- **드로어 내용**: `m3e-nav-menu`가 카테고리 안의 페이지를 나열합니다. 카테고리 이름은 이미 레일에 표시되므로 드로어에서는 반복하지 않습니다. 드로어의 항목은 텍스트만 표시하며, 배지와 중첩 그룹은 유지됩니다.
- **1600px 이상**: 현재 페이지가 카테고리에 속하면 드로어가 레일 오른쪽에 열린 채로 있으며, 콘텐츠의 너비를 가져갑니다. 열린 상태를 유지할지는 현재 라우트와 CSS 미디어 쿼리 둘 다에 달려 있으므로, 서버 렌더링과 첫 화면이 이미 최종 상태이고 새로 고쳐도 펼침 애니메이션이 재생되지 않습니다. 그 뒤로 창이 넓어지거나 하위 메뉴가 없는 페이지에서 카테고리로 들어가면, 너비가 공간 스프링을 따라 0에서 펼쳐지고 콘텐츠 영역이 자리를 내줍니다. 반대의 경우에는 같은 방식으로 접힙니다. 다른 카테고리에 포인터를 올리면 현재 목록이 페이드 아웃한 뒤 그 카테고리의 목록이 페이드 인합니다. 포인터가 내비게이션 영역을 벗어나면 현재 카테고리로 돌아옵니다.
- **960–1599px**: 포인터가 카테고리 위에 약 100ms 머물면 드로어가 레일 아래에서 미끄러져 나옵니다. 드로어는 페이지 전체 높이를 차지하며 앱 바와 콘텐츠를 덮습니다(레벨 3 그림자, 포인터가 드로어 안에 있는 동안은 레벨 5. 끝 쪽에 16px 둥근 모서리). 카테고리 사이를 이동하면 목록이 페이드 아웃했다가 다시 페이드 인합니다. 포인터가 레일과 드로어를 벗어나고 약 200ms 후에 드로어가 다시 들어갑니다.
- **960px 미만**: 레일과 드로어가 숨겨지고, 앱 바의 메뉴 버튼이 전체 내비게이션 드로어를 엽니다. 드로어의 최상위 메뉴는 레일과 일치하며 같은 아이콘을 표시하고, 하위 항목은 텍스트만 표시합니다. 드로어 위쪽은 둥근 모서리 없이 앱 바에 맞닿아 있고, 끝 쪽 아래에는 16px 둥근 모서리가 있습니다.
- **클릭**: 카테고리를 마우스로 클릭하면 그 첫 페이지로 이동합니다. 보조 키를 누른 채 클릭하면 브라우저에 맡겨져 새 탭이 열립니다. 터치스크린에는 호버가 없으므로, 카테고리를 탭하면 대신 드로어가 열리거나 닫히고, 바깥을 탭하면 닫힙니다. 드로어의 링크는 VitePress의 SPA 내비게이션을 쓰며, 클릭하면 드로어가 닫힙니다.
- **그룹**: 독자가 열거나 닫은 그룹은 드로어가 다른 카테고리로 바뀌었다가 돌아와도 페이지를 새로 고칠 때까지 그 상태로 유지됩니다. 그룹 안의 페이지로 이동하면 그 그룹이 열립니다.

모든 전환은 `m3e-theme`의 M3 Expressive 모션 토큰(`--md-sys-motion-spring-*`)을 쓰며, “모션” 설정에 따라 표준과 표현형 사이에서 바뀝니다. 시스템에서 “동작 줄이기”를 켜면 모든 것이 즉시 전환됩니다.

## 현재 페이지 찾기

- 라우트 비교에서는 `base`, 끝의 슬래시, 쿼리 매개변수, 해시를 무시하고, `.html`이 붙은 경로를 같은 경로로 취급합니다. `/guide/intro/`, `/guide/intro.html`, `/guide/intro?from=nav`는 모두 같은 항목과 일치합니다. 외부 링크와 앵커만 있는 링크는 현재 항목이 되지 않습니다.
- 현재 항목을 찾으면 조상 그룹에 `open`이, 항목 자체에 `selected`가 붙습니다. `m3e-nav-menu-item`은 `selected`를 `aria-current`로 매핑합니다. 병렬 페이지 그룹은 그룹 안의 어느 페이지에서든 선택됩니다.
- 객체로 작성한 내비게이션은 먼저 경로 길이가 긴 순으로 정렬되고, 현재 경로와 일치하는 첫 번째 키가 쓰입니다.

## 이전 페이지와 다음 페이지

본문 끝의 페이지 이동 카드는 병렬 페이지에만 나타나며, 같은 그룹의 페이지 사이에서만 이동합니다. 그룹에서 현재 페이지의 앞과 뒤에 있는 페이지를 가져오고, 제목에는 각 페이지의 탭 레이블을 씁니다. 그룹의 첫 페이지에는 이전 페이지가 없고 마지막 페이지에는 다음 페이지가 없습니다. 그룹에 속하지 않은 페이지에는 페이지 이동 카드가 나타나지 않으므로 독자를 다른 문서로 데려가는 일이 없습니다. 푸터의 링크 열은 전체 내비게이션 트리에서 가져오며, 여기서는 병렬 페이지 그룹이 항목 하나로 계산됩니다.

## 병렬 페이지 탭 바

### 위치와 모양

- 그룹의 모든 페이지는 표면 상단에 탭 바가 있으며, 좌우 여백은 히어로와 같습니다. 히어로가 있으면 탭 바 아래에 놓이므로, 그룹의 모든 페이지에서 탭 바가 같은 자리에 있습니다.
- 각 탭은 일반 링크이며, 클릭하면 SPA 내비게이션을 씁니다. 현재 페이지의 탭에는 `aria-current="page"`가 있고, `secondary-container` 배경의 인디케이터로 표시됩니다. 클릭하면 새 페이지가 로드되기를 기다리지 않고 인디케이터가 즉시 새 탭으로 미끄러집니다. 첫 번째나 마지막 탭으로 미끄러질 때는 바운스가 없는 곡선을 써서, 인디케이터가 둥근 끝을 넘어가지 않습니다.
- 탭 바는 이름이 있는 `<nav>` 랜드마크입니다(예: “아이콘 페이지”). 보조 기술에는 언제나 탭 바 사본 하나만 보이며, 이동 중인 사본은 포커스를 받을 수 없습니다.
- 현재 페이지의 탭을 클릭하면 아무 일도 일어나지 않습니다. 페이지 맨 위로 스크롤되지도 않습니다.

### 가로 스크롤

창이 좁아 모든 탭이 들어가지 않으면 탭은 너비를 유지하고, 탭 바가 가로로 스크롤되며, 아래쪽에 4px 두께의 얇은 스크롤바가 나타납니다. 독자가 직접 스크롤하기 전까지는 탭 바가 현재 탭이 완전히 보이도록 스스로 스크롤하고, 페이지가 바뀌거나 창 너비가 바뀌면 다시 맞춥니다. 독자가 휠, 드래그, 터치, 화살표 키로 스크롤하면 다음 페이지 전환 때까지 개입하지 않습니다. 스크롤은 탭 자체가 너무 넓을 때만 허용되며, 인디케이터 애니메이션이 끝을 넘어가도 스크롤바는 나타나지 않습니다.

### 앱 바에 도킹

- 아래로 스크롤하여 탭 바가 앱 바에서 24px 이내로 다가오면, 높이 40px의 컴팩트 탭 바로 줄어들어 앱 바 제목과 오른쪽 첫 번째 버튼 사이의 빈 공간을 채우며, 양쪽에 `--akari-app-bar-tabs-gap`만큼 간격을 둡니다. 원래 위치가 다시 앱 바에서 24px보다 멀어지면 페이지로 돌아갑니다.
- 두 위치 사이에서는 탭 바의 사본이 이동하며, 위치, 크기, 글자 크기, 배경색이 함께 전환됩니다. 가로와 세로 방향은 각각 M3 기본 공간 스프링으로 움직입니다. 표현형 모션은 감쇠비 0.8, 강성 380이고, 표준 모션은 0.9와 700입니다. 스프링은 정지 상태에서 시작하며, 표현형 모션에서는 끝에 살짝 바운스가 있습니다.
- 두 방향은 차례로 시작하며 일부 겹칩니다. 도킹할 때는 사본이 먼저 앱 바 아래에서 좁아지고, 빈 공간에 들어갈 만큼 좁아지는 순간 앱 바 아래쪽 가장자리를 지나 올라갑니다. 페이지로 돌아갈 때는 먼저 컴팩트 너비 그대로 내려온 뒤, 앱 바에서 벗어나면 펼쳐집니다. 두 번째 방향의 시작 시점은 두 스프링의 궤적으로 계산하므로, 앱 바 안에서 사본은 항상 빈 공간 안에 머뭅니다. 제목이나 검색 상자 위를 지나가지 않고, 잘리지도 않습니다.
- 사본의 도착 지점은 매 프레임 다시 측정되므로, 페이지가 아직 스크롤 중이어도 정확하게 도착합니다. 애니메이션 도중 스크롤 방향이 바뀌면 사본은 현재 위치에서 되돌아갑니다.
- 빠른 스크롤로 탭 바가 이미 앱 바 아래쪽 가장자리 밑으로 일부 밀려 들어갔다면, 사본은 먼저 아래쪽 가장자리에서 나와 앱 바 아래로 돌아온 뒤 위의 순서대로 도킹합니다. 탭 바를 담은 표면이 뷰포트 밖으로 완전히 스크롤된 뒤에야 탭 바가 돌아오는 경우(예: 푸터에서 앵커로 이동할 때)에는 날아갈 출발점이 없으므로, 앱 바 안의 탭 바가 그냥 페이드 인합니다.

### 제목과 공간 나누기

- 테마는 앱 바 제목(사이트 이름 또는 이를 대체하는 페이지 제목)을 잘리지 않은 너비로 측정하며, 제목이 바뀌거나 창 크기가 바뀌거나 글꼴이 로드되면 다시 측정합니다.
- 도킹할 때 탭 바는 먼저 콘텐츠 너비에 양쪽 간격을 더한 너비를 받습니다. 제목은 남은 너비까지만 쓰며, 그보다 길면 말줄임표로 잘립니다. 그런 다음 탭 바가 나머지 공간을 채웁니다.
- 탭 바가 앱 바에 도킹된 동안 제목 너비가 바뀌면(사이트 이름과 페이지 제목이 서로 바뀌거나, 제목 길이가 다른 페이지로 전환하면) 부드럽게 전환되며, 탭 바도 함께 늘었다 줄었다 합니다. 전환 중에는 제목이 말줄임표 없이 잘리고, 전환이 끝나면 말줄임표가 다시 나타납니다. 2px 미만의 차이로는 새 전환이 시작되지 않습니다.

### 앱 바 아래에 고정

- 탭 바는 제목이 적어도 로고, 버전, 약 6자(더 짧은 제목은 전체)를 유지할 수 있을 때만 앱 바에 도킹합니다. 탭 바가 도킹된 뒤에는 둘 중 어느 쪽이든 표시될 수 있으므로, 사이트 이름과 페이지 제목 모두 이 검사를 통과해야 합니다. 따라서 도킹 여부는 창 너비에만 달려 있으며, 스크롤하는 동안 앱 바가 제목을 바꿔도 번갈아 바뀌지 않습니다.
- 검사를 통과하지 못하면 탭 바는 앱 바까지 스크롤되었을 때 멈추고 그 아래에 고정되며, 레벨 2 그림자와 함께 살짝 떠올라 아래로 지나가는 본문 텍스트 위에 떠 있습니다. 주변의 텍스트는 계속 보이고 클릭할 수 있습니다. 그림자는 탭 바가 달라붙을 때 페이드 인하고, 떨어질 때 페이드 아웃합니다. 고정되어 있는 동안 `html`에는 `akari-tabs-pinned` 클래스가 있어, 앵커 이동과 목차의 고정 위치가 모두 탭 바를 위한 공간을 남기며, 글 제목이 탭 바 뒤로 스크롤되면 앱 바도 마찬가지로 페이지 제목으로 바뀝니다.
- 창이 넓어져 앱 바에 들어갈 수 있게 되면 탭 바가 앱 바 아래에서 앱 바 안으로 날아갑니다. 창이 좁아져 더 이상 들어가지 않으면 같은 방식으로 앱 바 아래로 날아갑니다. 사본은 앱 바에 아직 보이는 부분에서 출발하여(완전히 밀려났다면 너비가 0인 빈 공간의 위치에서 출발하여) 먼저 앱 바 아래로 내려온 뒤 펼쳐지며, 도중에 더 좁게 눌리지 않습니다.
- 창을 드래그하는 동안에는 검색 상자와 버튼이 아직 너비를 전환하고 있어 앱 바의 공간이 확정되지 않습니다. 그래서 테마는 공간이 안정되기를 약 200ms 기다린 뒤 도킹 여부를 결정합니다. 도킹된 탭 바가 더 이상 들어가지 않아 잘리게 될 때만 즉시 앱 바를 떠납니다.
- 본문 텍스트와 히어로는 각각 자체 쌓임 맥락을 이루므로, 그 안의 콘텐츠(코드 블록의 복사 버튼 등)는 고정된 탭 바 아래로 스크롤될 때 그 위로 떠오르지 않습니다.

## 페이지 전환 {#switching-pages}

그룹 안에서 페이지를 전환하면 문서 표면은 그대로 있고, 콘텐츠만 탭 방향에 따라 왼쪽이나 오른쪽으로 움직입니다(M3 공유 축 X). 오른쪽 탭으로 전환하면 현재 콘텐츠는 왼쪽으로 페이드 아웃하고, 새 콘텐츠는 오른쪽 30px 위치에서 미끄러져 들어옵니다. 반대 방향은 그 반대이며, 오른쪽에서 왼쪽 레이아웃에서는 방향이 좌우 반전됩니다. 탭 바 자체는 움직이지 않습니다.

- 탭 바가 앱 바에 도킹되어 있거나 그 아래에 고정되어 있으면 전환 후에도 그 자리에 머물고, 새 페이지는 본문 텍스트 시작 지점에 바로 맞춰 배치됩니다. 글 제목(히어로 또는 첫 h1)은 이미 앱 바(또는 고정된 탭 바) 아래로 스크롤된 상태이며, 앱 바는 새 페이지의 제목을 표시합니다. 새 페이지가 너무 짧아 그만큼 스크롤할 수 없으면 탭 바는 페이지로 돌아갑니다. 링크에 앵커가 있으면 앵커가 우선합니다. 브라우저에서 뒤로·앞으로 이동하면 이전 스크롤 위치가 복원됩니다.
- 탭 바가 페이지 안에 있으면 새 페이지는 평소처럼 맨 위에서 시작하고, 탭 바는 그 자리에 머뭅니다. 전환 전에 페이지가 조금 아래로 스크롤되어 있었다면 탭 바는 맨 위의 제자리로 부드럽게 돌아갑니다.

그룹을 떠나면 평소처럼 표면 전체가 페이드 아웃했다가 페이드 인합니다. 시스템에서 “동작 줄이기”를 켜면 탭 바와 콘텐츠 모두 즉시 전환됩니다.

## 접근성

- `m3e-nav-menu` 루트 요소에는 `aria-label`(“문서”)이 있으며, 페이지의 주 내비게이션 랜드마크입니다. 레일에는 자체 이름(“문서 분류”)이 있습니다.
- 레일에서는 화살표 키로 카테고리 사이에서 포커스를 이동하며, 카테고리 항목에는 `aria-haspopup`, `aria-expanded`, `aria-controls`가 있습니다. 960–1599px에서는 `Enter`나 Space로 드로어를 열고 포커스를 메뉴 안으로 옮기며, `Escape`로 드로어를 닫고 포커스를 카테고리로 돌려보냅니다. 1600px 이상에서는 현재 카테고리에서 `Enter`를 누르면 포커스가 열려 있는 드로어로 바로 이동합니다.
- 닫힌 드로어에는 `inert`가 있어 Tab 순서와 접근성 트리에서 빠집니다.
- 아이콘은 보조 기술에서 숨겨지며, 이름은 `label` 슬롯의 텍스트에서 가져옵니다. 내비게이션을 사용자 지정할 때는 “메뉴 루트 요소 + 라벨 안의 링크 + `selected` 상태” 구조를 유지하고, `div`로 링크를 흉내 내지 마세요.
