# 头图：技术细节

## 取色

带头图的页面从图片中取一个颜色作为主题的种子色。

- 使用 Material 官方的 [material-color-utilities](https://github.com/material-foundation/material-color-utilities)：把图片缩到 128px 以内，量化出主要颜色，再按是否适合作为界面主题打分。这套算法与 Android 从壁纸取色相同。透明像素与过于灰暗的颜色不参与。
- 取色在构建时完成，由 `.vitepress/media-colors.ts` 这个 Vite 插件负责：它扫描页面与 `public` 里的图片，构建出的 HTML 里直接带着颜色，页面打开时不再等图片、也不再读像素，服务端渲染与客户端水合用的是同一个值。
- 同一份结果也记下图片的像素长宽，用来在图片到达前撑出遮罩的尺寸；按图片文件的修改时间与大小缓存在 `.vitepress/cache/media-colors.json`，只有图片变化时才重新取样。改图后重新构建即可，不需要清缓存。
- 明暗两张图分别取色：白天用 `light` 图片的颜色，夜间显示 `dark` 图片时用 `dark` 图片的颜色。
- 远程图片在构建时下载一次取色，成功结果缓存 7 天；构建环境取不到时保持读者的颜色。也可以用 `color` 直接指定。
- 图片中找不到足够鲜明的颜色时，同样保持读者的颜色。

## 标题

配置头图后，页面标题显示在头图卡片中，Markdown 中的第一个 `# 标题` 被隐藏，页面仍然只有一个可见的 `h1`。标题文字取头部信息的 `title`，没有时取第一个 `#` 标题，与 VitePress 的页面标题规则一致。头图中的标题带 `data-akari-page-title`。标题滚到顶栏下方后，顶栏显示页面标题。

日期按页面语言格式化：`2026-05-19` 在中文页面显示为“2026年5月19日”，在英文页面显示为“May 19, 2026”。

## 排版

- 两张卡片占满文档表面的顶部，不受正文的 `--akari-doc-max-width` 限制。卡片到上、左、右三条边缘的距离，以及两张卡片之间的距离，都取 `--akari-doc-hero-inset`。卡片圆角与表面圆角同心。
- 标题字号与卡片内边距按头图自身的宽度缩放（容器查询），而不是按窗口宽度：导航抽屉展开、可用空间变窄时，标题随之缩小。
- 窗口窄于 840px 时两张卡片上下堆叠，文字在上，图片按 16:10 显示。
- 页面属于一组平行页面时，标签栏排在头图上方，头图在标签栏下方隔开同样的距离。这样组内各页的标签栏位置一致，在有头图与没有头图的页面之间切换时不会跳动。
- 图片带 `loading="lazy"` 与 `fetchpriority="high"`：在首屏时浏览器会立即加载它，并当作首屏最大的元素优先处理；窗口很窄、头图被排到首屏以下时，则等到接近视口再加载。头图在文档表面中，切换页面时随表面一起淡出淡入。

## 加载

- 正文图片在渲染 Markdown 时写入 `loading="lazy"` 与 `decoding="async"`，直接写在 HTML 里的 `<img>` 也一样；显式写出的 `loading` 或 `decoding` 不会被覆盖。
- 正文图片在浏览器中被包进 `.akari-lazy-media`：图片到达之前，一层遮罩盖住它，中间是 `m3e-loading-indicator` 加载球。遮罩的尺寸取图片在构建时记下的长宽，颜色取同一份取色结果；加载完成后按 MD3 的 `emphasized-accelerate` 淡出。`<picture>` 连同它的 `<source>` 一起包住，选择逻辑不受影响。
- 头图使用同一个加载球，覆盖在图片卡片上，遮罩同样应用那张图的取色；只等当前明暗模式显示的那一张。夜间那张图在白天不会被下载，反之亦然。
- 加载很快时遮罩不会闪：它延迟约 120ms 才淡入。淡出使用 MD3 的时长与缓动令牌；系统要求减少动态效果时不做动画，遮罩直接出现或消失。
- `ImagePreview` 组件里的缩略图有自己的外框：加载完成前按图片的构建期比例撑开，显示同一取色的加载球并拒绝点击；预览打开后，全图也先以相同比例和颜色出现加载球。不套正文这一层，以免改变它的圆角和点击区域。

## 图案与柔光

- 两张卡片用同一种图案。文字卡片的图案在末端上角最清楚，图片卡片的图案在起始下角最清楚。两处图案各自渐隐，合起来是一条对角线。
- 图片卡片的图案在图片之下，只在图片透明的地方露出。铺满的照片会把图案完全盖住。
- 指针停在卡片上时，周围会亮起一圈很淡的主题色柔光，柔光中的图案更清楚，边缘逐级淡出。指针移开时，柔光淡出。
- 柔光的位置由文档表面上的一个 `pointermove` 处理函数每帧写入（`--akari-light-x`、`--akari-light-y`），只响应鼠标与触控笔。
- 是否亮起同样按指针判断。读者用鼠标或触控笔时，`html` 带有 `data-akari-hover`，一触摸就会去掉该属性，不依赖 `(hover: hover)` 媒体查询。
- 图案在浏览器中挑选，服务端渲染时不带图案，挂载后淡入。因此服务端与浏览器的页面一致，不会出现水合差异。
- 触屏设备只显示静态图案，强制颜色模式下不显示装饰。装饰在文字与图片之下，不影响选择与点击。

正文中带背景的元素使用同一套图案，见[排版](/zh-CN/styles/typography/api#图案)。
