# サイドナビゲーション：詳細

## ナビゲーションレールとナビゲーションドロワー

- **レール**：ページの左側を全高にわたって占める帯で、アプリバーはその右側から始まります。`m3e-nav-rail` の中で、各カテゴリは `m3e-nav-item` です。子項目のあるカテゴリはその最初のページを指し、子項目のない最上位の項目はそれ自体がリンクです。右側の区切り線は、横にナビゲーションドロワーが表示されているときだけ現れます。
- **ドロワーの内容**：`m3e-nav-menu` がカテゴリ内のページを一覧にします。カテゴリ名はすでにレールに表示されているので、ドロワーでは繰り返しません。ドロワーの項目はテキストだけを表示します。バッジと入れ子のグループは保たれます。
- **1600px 以上**：現在のページがカテゴリに属している場合、ドロワーはレールの右側に開いたままになり、コンテンツから幅を取ります。開いたままにするかどうかは現在のルートと CSS のメディアクエリの両方で決まるため、サーバーレンダリングと最初の画面の時点ですでに最終的な状態になっており、再読み込み時に展開のアニメーションは再生されません。その後、ウィンドウが広くなったときや、サブメニューのないページからカテゴリに入ったときは、幅が 0 から、オーバーシュートしないスプリングで広がり、ドロワーの幅で減速して止まり、コンテンツの領域が場所を空けます。収納時も同じく、幅が 0 まで減速して縮み、コンテンツの領域がその分の場所を取り戻します。別のカテゴリにポインターを重ねると、現在のリストがフェードアウトしてから、そのカテゴリのリストがフェードインします。ポインターがナビゲーションの領域から離れると、現在のカテゴリに戻ります。
- **960–1599px**：カテゴリにポインターを約 100ms 置くと、ドロワーがレールの下からスライドして出てきます。ドロワーはページの全高を占め、アプリバーとコンテンツを覆います（レベル 3 の影。ポインターがドロワー内にある間はレベル 5。末尾側の角は 16px の角丸）。カテゴリの間を移動すると、リストがフェードアウトしてから再びフェードインします。ポインターがレールとドロワーから離れて約 200ms 後に、ドロワーはスライドして戻ります。
- **960px 未満**：レールとドロワーは非表示になり、アプリバーのメニューボタンで、すべてのページを含むナビゲーションドロワーが開きます。その最上位のメニューはレールと一致し、同じアイコンを表示します。子項目はテキストだけを表示します。ドロワーの上端は角丸なしでアプリバーにぴったり接し、末尾側の下の角は 16px の角丸です。
- **クリック**：カテゴリをマウスでクリックすると、その最初のページに移動します。修飾キーを押しながらのクリックはブラウザーに任され、新しいタブで開きます。タッチスクリーンにはホバーがないため、代わりにカテゴリをタップするとドロワーが開閉し、外側をタップすると閉じます。ドロワー内のリンクは VitePress の SPA ナビゲーションを使い、クリック後にドロワーは閉じます。
- **グループ**：読者が開いたり閉じたりしたグループは、ドロワーが別のカテゴリに切り替わって戻っても、ページを再読み込みするまでその状態のままです。グループ内のページに移動すると、そのグループは開きます。ドロワーにカテゴリの一覧が表示されているとき、そのグループはすでにその状態になっており、展開のアニメーションは再生されず、開閉のアニメーションは、読者がグループをクリックしたとき、または閉じたグループ内のページに移動したときにだけ再生されます。

すべてのトランジションは `m3e-theme` の M3 Expressive のモーショントークン (`--md-sys-motion-spring-*`) を使い、「モーション」の設定で標準とエクスプレッシブが切り替わります。システムで「モーションを減らす」がオンのときは、すべて瞬時に切り替わります。

## 現在のページの特定

- ルートの比較では、`base`、末尾のスラッシュ、クエリパラメーター、ハッシュを無視し、`.html` も同じパスとして扱います。`/guide/intro/`、`/guide/intro.html`、`/guide/intro?from=nav` はすべて同じ項目に一致します。外部リンクとアンカーだけのリンクが現在の項目になることはありません。
- 現在の項目が見つかると、その祖先のグループに `open` が、項目自体に `selected` が付きます。`m3e-nav-menu-item` は `selected` を `aria-current` に対応付けます。並列ページのグループは、グループ内のどのページでも選択状態になります。
- オブジェクトで書いたナビゲーションは、まずパスの長さで長い順に並べ替えられ、現在のパスに一致する最初のキーが使われます。

## 前のページと次のページ

本文の末尾のページ送りカードは並列ページにのみ表示され、同じグループのページ間だけを移動します。グループ内で現在のページの前と後にあるページを取り、タイトルにはそれぞれのタブのラベルを使います。グループの最初のページには前のページがなく、最後のページには次のページがありません。グループに属さないページにはページ送りカードが表示されないため、読者が別のドキュメントに移ることはありません。フッターのリンクの列はナビゲーションツリー全体から作られ、そこでは並列ページのグループは 1 つの項目として数えます。

## 並列ページのタブバー

### 位置と見た目

- グループ内のすべてのページで、サーフェスの上部にタブバーがあり、左右の余白はヒーローと同じです。ヒーローがある場合はタブバーの下に置かれるため、タブバーはグループのどのページでも同じ位置にあります。
- 各タブは通常のリンクで、クリックすると SPA ナビゲーションを使います。現在のページのタブには `aria-current="page"` が付き、`secondary-container` の背景を持つインジケーターで示されます。クリックすると、新しいページの読み込みを待たずに、インジケーターがすぐに新しいタブへスライドします。最初または最後のタブへのスライドにはバウンドのないカーブを使うため、インジケーターが丸い端を行き過ぎることはありません。
- タブバーは名前付きの `<nav>` ランドマークで、名前はたとえば「アイコンのページ」です。支援技術から見えるタブバーは常に 1 つだけで、移動中のコピーはフォーカスを受け取れません。
- 現在のページのタブをクリックしても何も起きません。ページの先頭にスクロールして戻ることもありません。

### 横スクロール

ウィンドウが狭くてすべてのタブが収まらないときは、タブは幅を保ったまま、タブバーが横にスクロールし、下部に 4px の細いスクロールバーが表示されます。読者がスクロールするまでは、タブバーは現在のタブが完全に見えるよう自分でスクロールし、ページの切り替えやウィンドウの幅の変化の後に位置を合わせ直します。読者がホイール、ドラッグ、タッチ、矢印キーのいずれかでスクロールすると、次にページを切り替えるまで干渉しなくなります。スクロールできるのはタブ自体の幅が足りないときだけで、インジケーターのアニメーションが端を行き過ぎても、スクロールバーが現れることはありません。

### アプリバーに収まる

- 下にスクロールしてタブバーがアプリバーから 24px 以内に近づくと、タブバーは高さ 40px のコンパクトなタブバーに縮み、アプリバーのタイトルと右側の最初のボタンの間の空きスペースを埋めます。両側には `--akari-app-bar-tabs-gap` の間隔があります。元の位置が再びアプリバーから 24px より離れると、ページに戻ります。
- 2 つの位置の間は、タブバーのコピーが移動し、位置、サイズ、文字サイズ、背景色が一緒にトランジションします。水平方向と垂直方向はそれぞれ M3 のデフォルトの spatial スプリングで動きます。エクスプレッシブなモーションでは減衰比 0.8、剛性 380、標準のモーションでは 0.9 と 700 です。スプリングは静止状態から始まり、エクスプレッシブなモーションでは終わりに少しバウンドがあります。
- 2 つの方向は順番に始まり、一部が重なります。収まるときは、コピーはまずアプリバーの下で幅を狭め、空きスペースに収まる幅になったちょうどそのときにアプリバーの下端を越えて上がります。ページに戻るときは、まずコンパクトな幅のまま下がり、アプリバーから離れてから広がります。2 つ目の方向の開始時刻は 2 つのスプリングの軌跡から計算されるため、アプリバー内のコピーは常に空きスペースの中に留まります。タイトルや検索ボックスの上を通ることも、切り取られることもありません。
- コピーの着地点は毎フレーム測り直されるため、ページがまだスクロールしている間でも正確に着地します。アニメーションの途中でスクロールの方向が変わると、コピーはその位置から引き返します。
- 速いスクロールでタブバーがすでにアプリバーの下端の下に一部隠れている場合、コピーはまず下端から出てアプリバーの下に戻り、その後で上の順序で収まります。タブバーを含むサーフェスがビューポートの外へ完全にスクロールした後でタブバーが戻る場合（たとえばフッターからアンカーへジャンプしたとき）、飛び立つ起点がないため、アプリバー内のタブバーは単にフェードインします。

### タイトルとスペースを分け合う

- テーマはアプリバーのタイトル（サイト名、またはそれに代わるページのタイトル）を省略しない幅で測り、タイトルが変わったとき、ウィンドウのサイズが変わったとき、フォントが読み込まれたときに測り直します。
- 収まるときは、まずタブバーにその内容の幅と両側の間隔が割り当てられます。タイトルは最大で残りの幅を使い、それより長い部分は省略記号で切り詰められます。その後、タブバーが残りのスペースを埋めます。
- タブバーがアプリバーに収まっている間、タイトルの幅の変化（サイト名とページのタイトルの入れ替わりや、タイトルの長さが異なる別のページへの切り替え）はスムーズにトランジションし、タブバーもそれに合わせて伸び縮みします。トランジション中、タイトルは省略記号なしで切り取られ、終わると省略記号が再び表示されます。2px 未満の差では新しいトランジションは始まりません。

### アプリバーの下に留まる

- タブバーがアプリバーに収まるのは、タイトルが少なくともロゴ、バージョン、約 6 文字分（それより短いタイトルは全体）を保てる場合だけです。タブバーが収まった後はどちらも表示されうるため、サイト名とページのタイトルの両方がこの判定を通る必要があります。そのため、収まるかどうかはウィンドウの幅だけで決まり、スクロール中にアプリバーのタイトルが入れ替わっても行ったり来たりしません。
- 判定を通らない場合、タブバーはアプリバーまでスクロールしたところで止まり、その下に留まります。レベル 2 の影で少し浮き上がり、下を流れる本文の上に浮かびます。その周りのテキストは見えたままで、クリックもできます。影はタブバーが張り付くとフェードインし、離れるとフェードアウトします。留まっている間、`html` には `akari-tabs-pinned` クラスが付きます。アンカーへのジャンプと目次の追従位置はどちらもタブバーの分の場所を空け、記事のタイトルがタブバーの後ろにスクロールすると、アプリバーも同じようにページのタイトルに切り替わります。
- ウィンドウがアプリバーに収まるほど広くなると、タブバーはアプリバーの下からアプリバーの中へ飛びます。ウィンドウが狭くなって収まらなくなると、同じようにアプリバーの下へ飛びます。コピーはアプリバー内でまだ見えている部分から（完全に押し出されている場合は、幅ゼロの空きスペースの位置から）出発し、まずアプリバーの下に下がってから広がります。途中でそれ以上狭く押しつぶされることはありません。
- ウィンドウをドラッグしている間は、検索ボックスとボタンがまだ幅をトランジションしており、アプリバーのスペースは確定していません。そのため、テーマは約 200ms 待って落ち着いてから、収めるかどうかを決めます。すぐにアプリバーから出るのは、収まっているタブバーが入りきらなくなって切り取られる場合だけです。
- 本文とヒーローはそれぞれ独自のスタッキングコンテキストを作るため、その中のコンテンツ（コードブロックのコピーボタンなど）が、留まっているタブバーの下にスクロールしたときにその上に浮かび出ることはありません。

## ページの切り替え {#switching-pages}

グループ内でページを切り替えると、ドキュメントサーフェスは動かず、コンテンツだけがタブの方向に左右に動きます（M3 の shared axis X）。右側のタブに切り替えると、現在のコンテンツは左へフェードアウトし、新しいコンテンツは 30px 右からスライドして入ります。逆方向ではその逆になり、右から左のレイアウトでは方向が反転します。タブバー自体は動きません。

- タブバーがアプリバーに収まっているか、その下に留まっている場合、切り替えた後もタブバーはその位置に残り、新しいページは本文の先頭に合わせて配置されます。記事のタイトル（ヒーローまたは冒頭の h1）はすでにアプリバー（または留まっているタブバー）の下にスクロールしており、アプリバーには新しいページのタイトルが表示されます。新しいページが短くてそこまでスクロールできない場合、タブバーはページに戻ります。リンクにアンカーがある場合は、アンカーが優先されます。ブラウザーの戻る・進むでは、以前のスクロール位置が復元されます。
- タブバーがページ内にある場合、新しいページは通常どおり先頭から始まり、タブバーはその位置に残ります。切り替える前にページが少し下にスクロールしていた場合、タブバーは先頭の元の位置にスムーズに戻ります。

グループから離れるときは、通常どおりサーフェス全体がフェードアウト・フェードインします。システムで「モーションを減らす」がオンのときは、タブバーとコンテンツはどちらも瞬時に切り替わります。

## アクセシビリティ

- `m3e-nav-menu` のルート要素には `aria-label`（「ドキュメント」）があり、ページの主要なナビゲーションランドマークです。レールには独自の名前（「ドキュメントのカテゴリ」）があります。
- レールでは、矢印キーでカテゴリ間のフォーカスを移動し、カテゴリの項目には `aria-haspopup`、`aria-expanded`、`aria-controls` があります。960–1599px では、`Enter` または Space でドロワーが開いてフォーカスがメニューに移り、`Escape` で閉じてフォーカスがカテゴリに戻ります。1600px 以上では、現在のカテゴリで `Enter` を押すと、開いているドロワーにフォーカスが直接移ります。
- 閉じたドロワーには `inert` が付くため、Tab の順序からもアクセシビリティツリーからも外れます。
- アイコンは支援技術から隠されており、名前は `label` スロットのテキストから取得されます。ナビゲーションをカスタマイズするときは、「メニューのルート要素＋ラベル内のリンク＋`selected` 状態」という構造を保ち、`div` でリンクを模倣しないでください。
