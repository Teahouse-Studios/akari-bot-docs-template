# ヒーロー：詳細

## 色の抽出

ヒーローのあるページは、画像から色を取り出してテーマのシードカラーにします。

- Material 公式の [material-color-utilities](https://github.com/material-foundation/material-color-utilities) を使います。画像を 128px 以下に縮小し、主要な色に量子化してから、インターフェースのテーマにどれだけ合うかで各色を採点します。これは Android が壁紙から色を取り出すのと同じアルゴリズムです。透明なピクセルと、くすみすぎた色は除外されます。
- 抽出はビルド時に行われ、`.vitepress/media-colors.ts` の Vite プラグインが担当します。ビルドされた HTML に色が入るため、ページを開くときに画像を待ったりピクセルを読んだりせず、サーバー描画とハイドレーションで同じ値を使います。
- 結果は画像ファイルの更新時刻とサイズをキーに `.vitepress/cache/media-colors.json` へキャッシュされ、変更された画像だけを再抽出します。画像を変えたら再ビルドするだけで、キャッシュを消す必要はありません。
- ライトとダークの画像は別々に抽出します。昼は `light` 画像の色、夜に `dark` 画像を表示するときは `dark` 画像の色を使います。
- リモート画像はビルド時に一度ダウンロードして抽出し、成功した結果は 7 日間キャッシュします。ビルド環境から取得できない場合は読者の色を維持します。`color` で直接指定することもできます。
- 画像に十分に鮮やかな色がない場合も、読者の色を維持します。

## 読み込み

- 本文の画像には Markdown の描画時に `loading="lazy"` と `decoding="async"` が付きます。HTML に直接書いた `<img>` も同じです。明示した `loading` や `decoding` は上書きしません。
- ブラウザーでは、本文の各画像が `.akari-lazy-media` で包まれます。画像が届くまでは覆いがかかり、中央に `m3e-loading-indicator` の球が表示されます。覆いの大きさはビルド時に記録した画像の寸法、色は抽出した色を使い、読み込みが終わると MD3 の `emphasized-accelerate` でフェードアウトします。`<picture>` は `<source>` ごと包むため、source の選択は変わりません。
- ヒーローも同じ球を画像カードの上に重ね、現在の明暗モードで表示している画像だけを待ちます。ダーク用の画像はライトモードではダウンロードされず、その逆も同じです。
- 読み込みが速いときは覆いがちらつかないよう、約 120ms 遅れてフェードインします。フェードアウトには MD3 の時間・イージングトークンを使います。減少した動きが設定されているときはアニメーションせず、覆いはすぐ表示・非表示になります。
- `ImagePreview` コンポーネントのサムネイルは独自の枠を持ち、読み込みが終わるまではビルド時の比率で枠を広げ、同じ色のローディングボールを出してクリックを受け付けません。プレビューを開いたときも、全画像が届くまでは同じ比率と色で球を出します。角丸やクリック領域を変えないため、本文の覆いでは包みません。

## タイトル

ヒーローを設定すると、ページのタイトルはヒーローのカードに表示され、Markdown の最初の `# Title` は非表示になります。そのため、ページに表示される `h1` は 1 つだけのままです。タイトルのテキストはフロントマターの `title` から取得し、ない場合は最初の `#` 見出しから取得します。これは VitePress のページタイトルの規則と同じです。ヒーロー内のタイトルには `data-akari-page-title` が付いており、アプリバーの下にスクロールすると、アプリバーにページのタイトルが表示されます。

日付はページの言語に合わせて書式化されます。`2026-05-19` は、中国語のページでは「2026年5月19日」、英語のページでは「May 19, 2026」と表示されます。

## レイアウト

- 2 枚のカードはドキュメントサーフェスの上部を埋め、コンテンツの `--akari-doc-max-width` には制限されません。カードとサーフェスの上端・左端・右端との距離、および 2 枚のカードの間隔は、すべて `--akari-doc-hero-inset` です。カードの角はサーフェスの角と同心円になります。
- タイトルのサイズとカードのパディングは、ウィンドウの幅ではなくヒーロー自体の幅に応じて変わります（コンテナクエリ）。ナビゲーションドロワーが開いて使える幅が狭くなると、タイトルもそれに合わせて小さくなります。
- ウィンドウの幅が 840px より狭いときは 2 枚のカードが縦に並び、テキストが上、画像が 16:10 で表示されます。
- ページが並列ページのグループに属している場合、タブバーはヒーローの上にあり、ヒーローはタブバーから同じ距離だけ下に置かれます。これにより、グループのどのページでもタブバーが同じ位置に保たれ、ヒーローのあるページとないページを切り替えてもタブバーがずれません。
- 画像には `loading="lazy"` と `fetchpriority="high"` が付きます。ファーストビューにある間はブラウザーがすぐに読み込み、その画面で最も大きい要素として優先します。ウィンドウが狭くヒーローがファーストビューの下に回り込んだときは、ビューポートに近づくまで待ちます。ヒーローは文書サーフェスの中にあり、ページを切り替えるとサーフェスと一緒にフェードします。

## パターンと光

- 2 枚のカードは同じパターンを使います。パターンはテキストカードの上部の末尾側の角と、画像カードの下部の先頭側の角で最もはっきりしており、そこから薄れていくので、2 枚を合わせると対角線を描きます。
- 画像カードのパターンは画像の下にあり、画像が透明な部分にだけ見えます。カードを埋める写真ではパターンは完全に隠れます。
- ポインターをカードに置くと、その周囲がテーマカラーでごくかすかに光ります。光の内側ではパターンが少しはっきり見え、光の縁は段階的に薄れ、ポインターが離れると光は消えていきます。ドキュメントサーフェスの `pointermove` ハンドラーが毎フレーム光の位置（`--akari-light-x`、`--akari-light-y`）を書き込み、マウスとペンにのみ反応します。 光が現れるかどうかもポインターで決まります。読者がマウスまたはペンを使っている間は `html` に `data-akari-hover` が付き、最初のタッチで外れます。`(hover: hover)` メディアクエリには頼りません。
- パターンはブラウザーで選ばれます。サーバーサイドレンダリングにはパターンがなく、マウント後にフェードインするため、サーバーとブラウザーのページが一致し、ハイドレーションの不一致は起きません。
- タッチデバイスでは静的なパターンだけが表示され、強制カラーモードでは装飾は表示されません。装飾はテキストと画像の下にあるため、選択やクリックの妨げになりません。

コンテンツ内の背景を持つ要素も同じパターンのセットを使います。[タイポグラフィ](/ja-JP/styles/typography/api#patterns)を参照してください。
