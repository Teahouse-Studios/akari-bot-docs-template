# 検索：詳細

## コンテナ変形 {#container-transform}

検索パネルはネイティブのモーダル `<dialog>` です。Web Animations API で作った M3 のコンテナ変形で展開します。言語の選択と設定ダイアログも同じ実装 (`useContainerTransform`) を使います。

- アニメーションするのは常に本物のパネルで、最初のフレームから最終的なサイズでレイアウトされています。開始時には、ボタンの形をした窓（`clip-path` のカプセル）がパネル自身の検索バーの先頭部分だけを見せ、平行移動でその窓をボタンの上に重ねます。そのため、最初のフレームは「アイコン＋プレースホルダー」の検索ボックスと同じに見えます。
- 展開につれて平行移動はゼロに戻り、窓はパネル全体（影を含む）まで広がります。内容は段階的に現れ、結果の領域と閉じるボタンは一緒にフェードインし、途中で何もないサーフェスが見えることはありません。アニメーションの終了状態はパネルの静止時のスタイルと同じなので、アニメーションを取り除いてもずれは生じません。
- ボタンのピクセルのコピーが窓の上に置かれ、窓と一緒に動きます。ボタンとパネルの内容はクロスフェードせず、一方がフェードアウトしてからもう一方がフェードインします（M3 のフェードスルー）。開くときは、まずコピーの下でパネルのサーフェスがフェードインし、次にコピーがフェードアウトし、その後パネル自身の検索バーがフェードインします。異なる 2 つのサイズのテキストが同時に見えることはありません。
- 閉じるときは来た経路をたどって戻ります。まず結果の領域と検索バーがフェードアウトし、途中でボタンのコピーがフェードインして引き継ぎ、その下でパネルのサーフェスがフェードアウトします。ボタンに戻る最後の区間では、エクスプレッシブなモーションのバウンドも含めて、見えているのはボタンそのものであり、本物のボタンとまったく同じ状態で終わります。そのため、背景のないボタン（歯車のボタンなど）でも、最後に背景の一部がちらつくことはありません。開閉が中断された場合は、現在のフレームからモーションが逆再生されます。
- 窓のサイズと角の半径は、ボタンの現在の位置とサイズから決まります。パネルの位置はアニメーションの開始時に改めて測定され、固定の座標には依存しません。

| モーション | 展開 | 折りたたみ |
| --- | --- | --- |
| 標準 | 約 300ms、`cubic-bezier(0.2, 0, 0, 1)` | 約 250ms、バウンドなし |
| エクスプレッシブ | 約 500ms、`cubic-bezier(0.38, 1.21, 0.22, 1)`。少し行き過ぎてから落ち着く | 約 400ms、同じカーブ。折りたたみ時に少しバウンドする |

システムの「モーションを減らす」設定がオンのときは、パネルはアニメーションなしで開閉します。ネイティブのダイアログが、最上位レイヤーでの表示、背景の不活性化、`Esc` で閉じる動作を提供します。開くとフォーカスは入力欄に移り、閉じると開く前の場所に戻ります。その要素がもう使えない場合は検索ボタンに戻ります。

## インデックスの構築

- インデックスは VitePress のローカル検索が作ります。サイトの Markdown レンダラーで各ページをレンダリングし、アンカーを持つ見出しでセクションに分割して、言語ごとに 1 つのインデックスを作ります。各インデックスは、ビルド時に 1 つのファイルにまとめられます。開発サーバーの実行中は、ページが変わるとインデックスが更新され、ブラウザーに送られます。
- パスとアンカーはレンダリングされたページから取られるので、書き換えられたパスや カスタムアンカー付きの見出しも含めて、ページの実際のパスと見出しの id に一致します。
- 本文は、タグを除いたレンダリング済みの HTML です。コードブロックも含まれるので、コード内の名前も検索できます。フロントマターに `search: false` があるページは除外されます。
- 中国語と日本語には空白がないので、`Intl.Segmenter` で単語に分割されます。テーマはクエリも同じ方法（`tokenizeSearchText`）で分割するので、クエリとインデックスは同じ単語で照合されます。

## 照合と順位付け

クエリはインデックスと同じ方法で単語に分割され、MiniSearch が照合します。

- 単語は、入力したとおりか、より長い単語の先頭として一致します。長い単語は、長さの最大 20% の編集距離までの綴りの誤りを許容します。
- すべての単語が一致する必要があります。すべてを含むセクションがない場合は、いずれかの単語を含むセクションが代わりに採用されます。
- 関連度は BM25 で、セクションの見出しの重みは 4、本文は 2、上位の見出しは 1 です。

そのうえで、結果は入力されたとおりのクエリによって段階的に順位付けされます。ここで「見出し」はセクション自身の見出しです。

| 段階 | 条件 |
| --- | --- |
| 4 | 見出しがクエリ全体と完全に一致 |
| 3 | 見出しがクエリ全体で始まる |
| 2 | 見出しがクエリ全体を含む |
| 1 | 上位の見出しまたは本文が、クエリ全体をそのまま含む（中国語のフレーズなど） |
| 0 | それ以外 |

段階の高いものが先に並びます。段階 4 と 3 では、ページがそのセクションより先に来ます。同じ段階の中では、MiniSearch の関連度、次に見出しの順です。URL ごとに残る結果は 1 つだけで、返されるのは最大 `maxResults` 件です。各結果は、一致した単語（`terms`）を持ちます。途中までの入力や綴りの誤りで一致した単語も含まれ、パネルがそれらをハイライトします。

言語ごとに独自のインデックスがあるので、結果は常に現在の言語のものだけです。

## 読み込みとキャッシュ

- 各言語のインデックスは、その言語で最初に検索するときに読み込まれ、その後はページ内にキャッシュされます。開発中は、インデックスが更新されるとキャッシュが消去されます。
- 入力は `debounce` でデバウンスされます。新しいクエリが入力されたときやパネルが閉じたときは、進行中のリクエストが `AbortSignal` で中止されます。
- インデックスの読み込みに失敗したり、形式が正しくなかったりした場合、パネルにエラーと再試行ボタンが表示されます。

## パネルの状態

| 状態 | 表示内容 |
| --- | --- |
| 入力が空 | 検索のヒントとショートカットの説明 |
| 読み込み中 | M3 の読み込みインジケーター |
| 結果あり | ページのタイトル、セクションの見出し、抜粋、ハイライトされた一致部分。現在の項目には `secondary-container` の背景が付く。リスト全体が 1 つのかたまりに見えるよう、丸くなるのは先頭の項目の上の角と最後の項目の下の角だけで、間の項目は角が四角です |
| 結果なし | 別のキーワードを試すよう促す案内 |
| 失敗 | エラーの原因と再試行ボタン |

結果を開くときは VitePress のルーターを通すため、SPA ナビゲーションが保たれます。入力欄、結果の一覧、エラーメッセージにはそれぞれ ARIA の名前があります。アプリバーのショートカットのヒントは `label-small` のタイプスタイルと完全に丸いキーキャップを使い、パネル内の矢印キー、`Enter`、`Esc` のヒントは `shape-extra-small` の角を使います。

## 既知の制限

- ローカル検索は単語を照合するもので、セマンティック検索や同義語には対応していません。必要な場合は、HTTP バックエンドか登録したバックエンドを使ってください。中国語と日本語の単語への分割はブラウザーの `Intl.Segmenter` に依存します。これがないブラウザーでは、空白と句読点でしか分割できません。
- ローカルインデックスが作られるのは、開発サーバーの実行中とビルド時だけです。開発サーバーが動いていないときに編集した Markdown は、次に `npm run dev` または `npm run build` を実行した後に検索できるようになります。
